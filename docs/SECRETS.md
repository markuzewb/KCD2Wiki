# Секреты и переменные окружения

В репозитории должны храниться только файлы проекта. Рабочие пароли, ключи и session-secret сюда не коммитятся.

Код обращается к секретам через переменные окружения:

| Переменная | Назначение |
|---|---|
| `WIKI_ADMIN_USER` | имя редактора, по умолчанию `admin` |
| `WIKI_ADMIN_PASSWORD` | пароль редактора, минимум 12 символов |
| `WIKI_SESSION_SECRET` | случайный секрет для подписи сессий, минимум 32 символа |
| `HOST` | адрес прослушивания, например `127.0.0.1` за Nginx |
| `PORT` | порт Node-сервера |
| `NODE_ENV` | `production` на боевом сервере |
| `WIKI_BASE_PATH` | префикс пути, например `/wiki` |
| `WIKI_DATA_DIR` | необязательный каталог данных вне кода |

## Локально

```bash
cp .env.example .env
# заполните .env локально, не коммитьте его
```

Node.js 20+ может прочитать файл при запуске:

```bash
node --env-file=.env server.js
```

Для Node.js 18 экспортируйте переменные вручную или используйте systemd/docker.

## Свой сервер / systemd

Создайте файл вне репозитория, например `/etc/kcd2rp-wiki.env`:

```bash
sudo install -m 600 /dev/null /etc/kcd2rp-wiki.env
sudo nano /etc/kcd2rp-wiki.env
```

Пример содержимого:

```ini
HOST=127.0.0.1
PORT=3082
NODE_ENV=production
WIKI_BASE_PATH=/wiki
WIKI_ADMIN_USER=admin
WIKI_ADMIN_PASSWORD=СГЕНЕРИРУЙТЕ_ДЛИННЫЙ_УНИКАЛЬНЫЙ_ПАРОЛЬ
WIKI_SESSION_SECRET=СГЕНЕРИРУЙТЕ_СЛУЧАЙНЫЙ_СЕКРЕТ
```

Сгенерировать случайный секрет:

```bash
openssl rand -hex 32
```

Служба `deploy/kcd2rp-wiki.service` уже использует:

```ini
EnvironmentFile=/etc/kcd2rp-wiki.env
```

После изменения секретов перезапустите службу:

```bash
sudo systemctl restart kcd2rp-wiki
```

## Если секрет попал в репозиторий

1. Немедленно сгенерируйте новый пароль/секрет и обновите его на сервере.
2. Удалите файл из индекса и истории Git, если репозиторий публичный или будет опубликован.
3. Считайте старое значение скомпрометированным, даже если коммит уже удалён из ветки.

Статическая сборка для GitHub Pages не включает `.env`, пароль редактора или session-secret.
